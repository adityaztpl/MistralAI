# 03 - Evaluation Metrics and Human Feedback

AI content products need quality measurement. A capstone that only generates text is a demo. A capstone that measures, reviews, and improves output is a product system.

This guide defines a rubric for Instagram content packs generated by the CrewAI/Mistral workflow.

## Learning goals

- Build a quality rubric for captions, hashtags, strategy, and safety.
- Distinguish automated evaluation from human review.
- Store prompt/model/eval metadata.
- Use feedback to improve future generations.
- Explain model quality trade-offs in interviews.

## What to evaluate

The existing crew produces:

- market research;
- content strategy;
- visual content concepts;
- captions;
- final content pack.

Evaluate both the pieces and the final pack.

## Rubric dimensions

| Dimension | Weight | What good looks like |
| --- | ---: | --- |
| Brand alignment | 20% | Tone, values, and audience match the brand description |
| Topic relevance | 15% | Posts directly address the requested campaign/topic |
| Caption quality | 20% | Hooks, clarity, CTAs, readability, platform fit |
| Hashtag quality | 10% | Relevant, diverse, not spammy, balanced specificity |
| Visual usefulness | 10% | Visual prompts are actionable for a designer/creator |
| Strategy coherence | 10% | Calendar has logical flow and distinct post goals |
| Safety/compliance | 10% | Avoids prohibited claims, sensitive content, or risky advice |
| Output completeness | 5% | Required number of posts and sections are present |

Total score: 0-100.

## Scoring scale

Use a 1-5 scale for each dimension:

| Score | Meaning |
| --- | --- |
| 1 | Poor; likely unusable |
| 2 | Weak; major edits required |
| 3 | Acceptable draft; needs review |
| 4 | Strong; minor edits |
| 5 | Excellent; publish-ready with normal approval |

Then compute weighted score.

## Automated checks

Start with deterministic checks:

- required artifact files exist;
- final pack includes requested number of posts;
- captions are not empty;
- hashtag count is within target range;
- captions are below platform length limits;
- no banned words/claims for configured industry;
- no duplicate captions;
- no obviously broken placeholders like `{topic}`;
- each post has CTA and alt text if required.

These checks are cheap and explainable.

## LLM-as-judge checks

Use carefully. An evaluator model can score:

- brand alignment;
- topic relevance;
- tone consistency;
- caption quality;
- strategy coherence.

Controls:

- use a stable evaluation prompt version;
- include the rubric explicitly;
- ask for JSON output;
- require short rationales;
- cap tokens and cost;
- compare evaluator scores with human feedback;
- do not let evaluator replace human approval for publishing.

## Human feedback loop

Capture feedback at multiple levels:

| Level | Feedback |
| --- | --- |
| Run | overall rating, safe-to-publish, notes |
| Post | thumbs up/down, edited caption, hashtag edits |
| Dimension | brand voice score, relevance score, compliance flag |
| Artifact | final pack approved/rejected |

Use feedback for:

- dashboard quality trends;
- prompt improvement;
- few-shot examples from approved outputs;
- tenant-specific brand voice profile;
- regression tests.

## Data model

| Field | Notes |
| --- | --- |
| `RunId` | Parent run |

| Field | Notes |
| --- | --- |

## Quality gates

Define what happens by score:

| Score | UX/action |
| --- | --- |
| 85-100 | "Strong draft" badge; normal review |
| 70-84 | "Needs light review" badge |
| 50-69 | "Needs edits" badge; show warnings |
| < 50 | "Regenerate or revise inputs" warning |

Quality gates should guide reviewers, not hide output without explanation.

## Prompt/version tracking

Store:

- model id;
- temperature;
- max tokens;
- agent config version;
- task config version;
- evaluator version;
- code version/commit if available;
- created timestamp.

This lets you answer:

- Did quality change after a prompt update?
- Did a model change improve hashtags but hurt brand tone?
- Which outputs were created under an older policy?

## Evaluation test set

Create a small golden dataset:

| Brand | Topic | Expected behavior |
| --- | --- | --- |
| Specialty coffee | Morning rituals | Warm, practical, no medical productivity claims |
| Fitness coach | Beginner strength | Avoid unsafe health claims; include disclaimers |
| B2B SaaS | SOC 2 readiness | Professional tone; avoid fake compliance guarantees |
| Bakery | Holiday preorders | Local, sensory, clear CTA |
| Nonprofit | Volunteer drive | Mission-focused, inclusive, specific CTA |

Run the same prompts after changes and compare scores and human ratings.

## Failure taxonomy

When a run is bad, label why:

- weak input from user;
- model hallucination;
- prompt too vague;
- missing brand voice data;
- unsafe or unsupported claim;
- repetitive captions;
- hashtag spam;
- wrong audience;
- output format drift;
- provider failure/truncation.

This taxonomy helps interviews because it shows you can diagnose quality instead of saying "LLMs are unpredictable."

## Interview prompts

- How do you know the generated captions are good?
- What can deterministic checks catch that LLM judges should not?
- How do you prevent an evaluator model from becoming arbitrary?
- How would you use human feedback without overfitting?
- Which metrics would you show to a product manager?
- How do you compare model A vs model B?

## Done criteria

- [ ] Rubric exists and is documented.
- [ ] Every run stores model/prompt/eval metadata.
- [ ] Deterministic checks run after artifacts are written.
- [ ] Human feedback is captured in the UI.
- [ ] Dashboard shows quality trend or latest score.
- [ ] Regression examples exist for at least five brand/topic pairs.
